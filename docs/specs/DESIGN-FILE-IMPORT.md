### 键盘与警告框的材质、阴影和复合路径

苹果原件的 iPad 键盘底板从下到上叠加四层纯色，包含 Plus Darker、Plus Lighter 与明度混合。Forma 保留每一层的颜色、混合模式和透明度，画布、原型、React 及静态导出在绘制时合成。独立的内外阴影按源顺序绘制。中性色的 Plus Darker 按背景 RGB 通道减色，再按阴影透明度混合。包含图像、渐变、彩色 Plus Darker 或受裁剪的外阴影，继续按导入报告复核。[W3C 合成与混合](https://www.w3.org/TR/compositing-1/#generalformula)

在 Sketch 234013 的临时副本中，将键盘五层阴影全部设为普通混合，5,688 个像素的 RGB 差超过 8，均落在旧版输出的超差区域。单独切换这两个源对象上的玻璃效果没有改变它们的像素。保留全部几何、两端单独关闭文字并比较白底 1× 渲染，警告框可编辑运行时为 1,245/351,348，键盘为 151/517,880。静态 PNG 分别为 1,565/351,348 与 2,497/517,880；警告框裁到原画板范围。此项实验只隔离图形材质，完整画板仍按上方六对象标准复验。

原稿 282 个复合形状中，220 个多轮廓组没有显式布尔操作，14 个组混用操作。导入保留父层填充规则和每个操作数的顺序。选中复合组可以更换整组运算，选中直接子路径可用「子路径运算」切换保留轮廓、联集、减去顶层、交集或排除重叠。锁定图层与未分离的实例沿用几何保护。重新打开及工程导出保留孔洞和各个可编辑的操作数。

用 `npm run test:browser -- group-tint` 重跑各输出的实像素回归。四色材料在三种输出均为 RGB(51,51,51)，RGB(128,128,128) 背景上的 50% 中性减色阴影均为 RGB(77,77,77)。`tests/sketch-import.test.ts` 检查复合路径的源顺序、孔洞与子路径编辑后重新求值。

### 可编辑嵌入字体与源文字位置

Sketch 导入 Worker 以本地 HarfBuzz WASM 读取原文件字体。字体资源 ID、PostScript 名称、OpenType 命名实例、字号与特性决定字形。读 `fvar` 和 `name` 后，SF Pro 的 Medium 使用 510、Semibold 使用 590。AAT `trak` 正常字距按源字号计算并叠加作者设定的字距。以本机 CoreText 读取 SF Pro Bold 38 pt 的 “APPLE DESIGN RESOURCES” 为例，作者字距 3.2 对应整行 569.104 pt，原稿自适应框为 570 pt。[OpenType fvar](https://learn.microsoft.com/en-us/typography/opentype/spec/fvar) · [Apple AAT trak](https://developer.apple.com/fonts/TrueType-Reference-Manual/RM06/Chap6trak.html) · [HarfBuzz](https://harfbuzz.github.io/shaping-and-shape-plans.html)

文档的 `sourceTextLayout` 缓存字符串、字号/轴等排版属性键、原始宽高、各行的 Unicode 字符坐标与基线。画布、预览及独立 React 工程使用文档字体着色，保留可选择和编辑的文本。字色变更复用坐标。字符、字号、字体、字间距、行高或宽高改变时重新排版。源文件的自动宽高在可用缓存下参与父层尺寸计算。浏览器按设备像素取整 SVG 视口时，运行时补回画板内的小数位置。

混排富文本、连写或多字符组合簇、从右向左的段落及需要额外回退字库的字符使用浏览器文字排版。换行缓存覆盖显式换行和可按空格断行的 ASCII 段落。两条路径都保存原 Unicode。自建测试字体覆盖软换行、补充平面字符、组合附标、命名实例字重、字距和样式编辑后的失效，测试入口为 `tests/sketch-text-layout.test.ts`。本机 Chromium 100% 从完整 Apple 原件导入后，72 × 50 的 Buttons/Dark/Large/Bordered/Text/1 - Idle 对原厂图的最大 RGB 通道差为 10，3,600 个像素均在阈值 16 内。对原厂单独导出的 38 pt 封底署名和 134 pt “iOS” 标题，570 × 45 与 640 × 160 的字形 Alpha 蒙版逐像素相同。设备、字体栅格器及缩放比例共同决定像素验收适用范围。

### Figma 本地文件的原稿字体几何

单段单色文字在 `derivedTextData`、字体、内容与派生布局框相符时保留 `sourceTextShape`。本机安装同名字族的情况也采用原始轮廓。字符、字号、字体、间距或布局框改变时重新排版，修改字色时继续着色原轮廓。1× 视图按字形轮廓的覆盖率绘制小字，高分屏、变焦、大字及外伸笔画保留可缩放 SVG。文字使用独立原生节点，画布编辑和辅助技术能取得原 Unicode 字符串。

以 `scripts/check-apple-figma-import.mjs` 从正常文件选择器打开 160,736,706 字节的 Apple Figma 本地副本。脚本核验其 SHA-256、46 页源顺序、所有主件及变体关联、共享样式及字形层数。关闭后在干净浏览器重新打开保存的文件，原位编辑警告框标题，检查中文、组合字符和 emoji 的可见结果，撤销后重新检查原始字形。独立安装、构建并运行完整 React 工程后，分别对照预览、React 和同一源节点的原厂 1× 图像。

### 整体着色与源字体排印

Sketch 组或实例的单色 Tint 写入 `style.tint={color,opacity}`。子树先完成图形、描边和透明度合成，再替换 RGB，合成后的 alpha 乘以 Tint 的不透明度。已导入 Tint 的单选图层在设计面板显示「整体着色」，颜色与百分比沿用原有取色器、事务和撤销。画布、原型预览及 React 工程共用 `nodeCss` 生成的过滤器，静态 SVG 和 PNG 共用相同的 SVG 原语。原稿中使用颜色变量的 Tint 当前保留解析时的颜色值，并在导入报告中记录。 [Sketch Tint](https://www.sketch.com/docs/components-and-styles/styling/tints/)

用 `npm run test:browser -- group-tint` 重跑像素回归。它检查重叠两个 50% 图层后再乘 60% Tint，另核对品红底上青色正片叠底、面板修改/撤销、保存重开、画布、原型和 PNG。原始 Spinner 的 35 × 35 像素经过 Sketch 原厂 PNG 对照。原厂与三个输出的峰值像素均为 RGBA(235,235,245,153)。对预乘 RGB 及 alpha 设置 16 级容差，画布和运行时各 24/1,225 像素超过阈值，静态导出 18/1,225。差异计入验收。

嵌入的 Apple 字体如提供 AAT 水平正常字距表 `trak`，适配器读取 `head.unitsPerEm`、字号和字体单位，按字号内插，区间外采用最近端点；作者指定的字间距优先。真实 SF Pro 的 17 pt 常规与斜体均得到 −0.431640625 px。 [Apple AAT trak 表](https://developer.apple.com/fonts/TrueType-Reference-Manual/RM06/Chap6trak.html)

主件的编辑背景、导出背景和实例背景按源标志分别生效。Sketch 栈的绘制顺序保留在图层树中，横向和纵向排列按源方向计算。富文本存储原 Unicode 和 UTF-16 区间；名称中的私用区字符按嵌入字体逐字回退。字形效果只作用于文字轮廓，内外阴影和图层组着色保留子树透明度。[Sketch 实测映射](../requirements/SKETCH-IMPORT-RESEARCH.md)

## 0.8.0 实际操作与兼容范围（历史基线）

在 Forma 菜单选择「打开设计文件…」，选择本机的 `.sketch` 或 Figma Design 的 `.fig`。文件管理器、顶栏的「导入设计文件」、向画布拖放单个原稿和 macOS「打开方式 → Forma」也使用这个读取器。导入在本机进行，无需连接模型网关。Figma 链接需先在有权限的 Figma 编辑器中保存本地副本。

预检列出源记录、页面、展开后可选图层、组件、实例、样式和图片。展开实例所得的子层计入可选图层，内部定义和资源记录也可计入源记录，两者分母不同。核对兼容性说明后选择「导入为新文件」。关闭预检会终止读取；校验失败或取消时不会创建副本。写入本机存储后才能打开新文档。可在「查看导入报告…」搜索说明、定位仍存在的目标图层，或下载 JSON。报告会随 Forma 文件保存。

## 工程设计与后续兼容目标

以下保留实施前的设计决策和完整保真验收条件。其中选页、重新绑定外部库、授权链接输入、四类处置的逐属性覆盖率，以及逐画板达标，仍属扩展目标。0.8.0 实际入口与验收范围以上表为准。

### 一条转换管线，两种格式适配器

1. **识别并清点**。Web 传入字节或 Blob，Electron 通过受限桥接读取设计师选择的同一文件。在解压前识别容器头、条目及版本；同时限制实际解压字节、条目数、解码像素、树深与实例展开规模。拒绝损坏、重名冲突、路径越界及未知必需编码。主线程只展示文件、阶段计数与取消。
2. **提取来源模型**。适配器输出文档版本、页目录、定义表、图层记录、资源目录和诊断。每层保留源 ID、父 ID、同级位置、原名、原文、原始单位、局部变换、可见/锁定、样式栈和引用。Sketch 按文件与页引用读入；Figma 按内嵌协议将记录还原为最终场景，区分删除记录、用户页面、内部定义与实例覆盖。先建索引再连边，支持定义在后页的情况。
3. **分配身份、解析依赖**。用源文档身份、对象种类及源 ID 分配稳定目标 ID，记录映射表；无原生持久文档 ID 时用导入快照命名空间。显示名称永不充当主键。遇到源语言重名、源 ID 跨类别复用或 Forma 长度/唯一性限制时保留原值及双向映射。每次打开另存独立文件，文件键单独生成。选择单页时递归取得该页用到的主件、样式、变量别名、位图和字体引用；同名远程库只按稳定标识与版本匹配。
4. **生成 Forma 文档**。两端共用一个映射器，从有序定义生成设计系统与组件库，再建页、原生图层和实例，最后应用覆盖、布局与交互。活动页写根级 `nodes`，其余页写 `pages[].nodes`。保留本地实例 `templateKey`、嵌套交换和主件链接。共享实例模板与画布上展开的图层分别计数，展开预算包含跨页与递归依赖。
5. **清点后提交**。先做源→目标双向对账，再过 `parseDocument`、库/变量和资产引用校验。临时数据在提交前与当前工作稿隔离。新文档、目录项和持久化导入报告需要共同提交；若资产分块写入，则先暂存、以单事务发布清单，取消或失败清理未引用块。仅在存储提交完成后打开新文件；重复点击同一任务只提交一次。原生 Forma 打开与恢复流程继续单独回归。

建议模块边界为 `src/infrastructure/design-import/{sketch,figma}/`（读取）、`src/application/design-import/`（编排、取消、提交），源数据转原生契约的纯函数放在领域边界。编辑器、预览与工程只消费通过校验的 Forma 文档。来源信息用显式、版本化的可选结构持久化，能随设计文件迁移，禁止只挂临时 JS 属性；本次实测现有 Zod 会移除未声明字段。若需新增仿射矩阵、复合样式或源对象类型，要在同一里程碑贯通编辑、撤销、保存、预览和导出。[当前架构](../ARCHITECTURE.md)

## 最容易破坏设计稿的映射

| 源特性 | Forma 处理及可验证行为 |
| --- | --- |
| 父子、层叠、几何 | 存父局部矩阵与画板原点；单独处理旋转轴心、负坐标、镜像和裁剪。Sketch 验证有序子层，Figma 验证父索引与 position 排序。用暗/浅重叠层实际点选，逐层对比四角。页面列表顺序、绘制顺序和图层面板显示顺序分别核对。 |
| 文本、字体、混合语言 | 严格解码；字符串与标记的区间单位分别转换，保留换行、首尾空格、组合重音、RTL、ZWJ 和私用码点。校验字体名、字重、行高、字距、段落方向与逐行断点。字体缺失时能定位和统一替换，正文始终可编辑；未经源端证明不臆测私用区字符含义。 |
| 主件、变体、实例 | Sketch Symbol 主件按 symbolID 注册；Figma 组件集保留变体属性、排列与同名不同 ID，区分主件和实例。保存嵌套覆盖路径、文字、显示和组件交换。保留“显式覆盖恰好等于默认值”的标记；修改主件后只有未覆盖属性应联动。 |
| 共享样式、变量、颜色 | 分开存定义、节点绑定、局部覆盖及有效值。Sketch 组合 Layer Style 跨 paint/effect 域时保留同一来源与联动；Figma 填充/描边样式可分别绑定，当前 Forma 单一 paint 槽若无法表达，先扩契约。核对多重填充顺序、渐变控制点、透明度、颜色空间、别名/模式。切换主题和修改共享样式后再比一次。 |
| 布局、矢量、材质 | 对可表达的约束、自动布局映射 Fixed/Hug/Fill、子层例外、间距和内边距；在第二种父宽复验。保留矢量网络、布尔操作数和蒙版作用域。玻璃、背景模糊、特殊滤镜按局部区域对照不同背景。单帧相似的静态效果只能登记为参考外观。 |
| 图像、交互 | 位图按原始字节去重，保留裁切矩阵、倍率、P3/ICC 与单次使用的位置。仅迁移源稿显式声明并可由运行时表达的交互；未支持的触发或动作定位到源节点。禁止根据图层名自行推断按钮动作。 |

## 导入界面和异常处置

- 从“文件 → 导入设计文件…”及文件管理器进入。同一份预检显示格式、版本、页面、图层、主件/实例、样式、资源和缺失项。小窗口保持页列表与问题列表可滚动，键盘能选择、定位、取消；图标沿用全局提示规范。
- 结果使用“可编辑”“近似”“仅参考”“阻断”四种处置，分别统计对象、属性和引用。整页转成图片会将其后代全部记为仅参考。完整导入必须满足支持矩阵全部关键断言。若只适合参考，界面明确显示可编辑范围，由设计师主动选择保留局部参考或取消；没有可信参考图时显示该源对象及原因。
- 页面可选时同时给出整稿规模、所选范围及依赖；避免隐式截取。外库可由用户提供同源版本后重新解析。整稿超过现有能力时，记为该格式/样本完整导入未通过；选页可用单独记账。
- 大文件可取消，阶段文案区分“已解码”“已校验”“已保存”。解析与导入默认本机运行，不执行源文件中的 JS、插件或嵌入内容；Figma 链接通过授权官方接口，只读取选定范围与必要依赖。Apple 样本作本机比对，自制可分发样本用于仓库和 CI。

- 负间距的自动布局通过 flow 项间的负边距绘制。保留实际数组顺序、首项最前的视觉顺序以及蒙版之后同级节点的 alpha/亮度/矢量范围。浏览器 `source-layout` 验证同一输入在编辑画布、预览与选区 PNG 上的独立实色像素、50% 蒙版、跨越范围的先前兄弟与重叠顺序。

### Figma 连续圆角及透明材质

原稿的两条相邻边共享圆角平滑余量。四角等半径且达到短边一半时，曲线为圆弧。源圆角和原布局尺寸随原生文件保存。简单单色胶囊在设备像素对齐、显示尺寸与原始尺寸一致时，沿实际圆弧按 16×16 取样并量化为 16 级覆盖。缩放、旋转和高分辨率下按当前尺寸使用可缩放的圆角轮廓。所有采样来自可编辑几何，文字、子层与变量独立。旋转、裁切、位图、分侧描边和复杂填充仍走各自的绘图路径。前景模糊的源直径换算到 CSS 高斯标准差。

`style.figmaGlass` 保留原始霜化、折射、介质密度、色散和镜面参数。无霜化、无色散和无镜面高光的圆角玻璃，可对平直图层树里的不透明纯色背板作局部采样，使背板边缘在玻璃下发生颜色扩散。该近似取样按背板和透镜的当前尺寸、位置、圆角及主题颜色计算。网页预览会在尺寸变化时更新，静态绘图使用导出场景的背面内容。旋转背板、位图或渐变背板、非均匀镜面高光和色散仍需查看逐层报告。该模型未取得 Figma 原厂着色器的实现。

原厂从所属 Section 和组件集采样底色。独立导出控件时，Forma 只在需要的玻璃轮廓下补回直达光背景，已在画布上绘制的祖先保留一次。透射通道按各层源透明度进行复合。0.8 px 等亚像素高斯在小型纯色圆角背板上由同一分离卷积求值，按设备像素比更新遮罩。工作预算为 20 万采样像素、单轴卷积半径 80、每轴 700 万个半径与像素的乘积。预算外使用可缩放的浏览器模糊。原始半像素 Linear Burn 描边按各色通道与轮廓覆盖计算。纯白 Multiply 面上的加色内阴影达到白色上限时只绘制一次轮廓。

### Figma 堆叠填充的变量引用

一层对象有多层纯色填充时，每一层都要独立保留源变量、颜色与有效透明度。顶层到下层的 `style.paints[]` 用 `colorVariableId` 引用颜色，用 `opacityVariableId` 引用随模式变化的数值 Alpha。检查方法是在两种模式间切换、保存重开、将组件引入另一文档，并在导出 CSS 中检查变量引用。源稿把样式 GUID 两段都设为无符号整数最大值时，实例覆盖语义是解除绑定。模式表中只有集合 ID 的记录按父级继承。

### Figma 多重描边

矩形、椭圆和框的 2–16 层纯色描边写入 `style.strokePaints`。面板从顶漆起排列，每层可调整颜色、透明度、混合模式、次序、可见性与变量。线宽、分侧宽度、对齐与虚线由各层共享。画布、预览、静态绘图和 React 工程按相同轮廓由底向顶绘制各层。

Figma 的共享颜料可用于描边。关联样式更新后，原稿中可同时存在旧的节点颜料缓存和当前共享样式。画布显示关联样式，节点保留归档中的漆值。遇到显式实例覆盖或设计师编辑某一漆的颜色时，`styleOverrides` 以漆 ID 和属性记录；修改共享底色或顶漆透明度仍能联动。局部漆层数量或次序与共享样式不同时，保留局部绘制顺序与共享引用。Apple 原件有 286 个双描边对象，其中 134 个绑定共享样式，59 个关联单漆、75 个关联双漆。原厂两个独立描边控制的右侧与底侧取色分别核对 40 及 3,930 个像素。 逐层统计以二进制归档中的 `styleIdForStrokeFill` 为准。对照原厂插件，`492:46326` 返回一层白色 Linear Dodge 和有效样式 ID；`492:46987` 返回两层及空样式 ID，归档中的共享 GUID 仍能解析，显示的浅灰顶漆也与该样式一致。它的 35×40 原厂独立图中，整个右边缘 40 个像素均在每通道 16 的容差内，最大通道差为 12。Forma 保留归档中的引用。两条独立矢量描边样式保留路径外观，并在导入报告列明。含图片或无法表达的多重描边继续报告近似。用 `npm run test:browser -- stroke-paints` 检查蓝色背板上的正片叠底和滤色、重排、显隐、保存重开与静态 PNG，再运行 `npm run test:exports -- stroke-paints` 独立安装构建并检查工程像素。0.8.3 的 Chromium、Firefox 和 WebKit 均通过该链路。编辑与预览在三种引擎的采样均为 RGB(51, 51, 166)，静态 PNG 在 Firefox 为 RGB(51, 50, 165)，其余两种为 RGB(51, 51, 166)。

### 线性渐变坐标与路径填充

原生 Figma 线性渐变在图层归一化坐标 `u=x/width`、`v=y/height` 上按 `t=m00*u+m01*v+m02` 取色。原生设计文件需保留这三个系数、色标和透明度。改图层宽高或色标后仍按当前尺寸求值；显式修改角度时使用设计师输入的新方向。用非正方形、轴向、斜向、反向和画板外色标检查画布、静态导图及工程。色标、路径和图层尺寸都能单独编辑。[Figma 渐变定义](https://developers.figma.com/docs/widgets/api/type-GradientPaint/) · [openfig-core 二进制矩阵说明](https://github.com/OpenFig-org/openfig-core/blob/main/docs/gradients.md)

渐变可编辑色标上限为 64。四个 36 × 36 原始图层各含九个角度渐变色标，其中三个另叠一层径向渐变。导入保留全部色标、两层的前后关系及各自的仿射矩阵。径向渐变以逆矩阵变换中心和半径，轴对齐椭圆在网页按两轴半径绘制，静态 SVG 直接采用逆矩阵。偏轴剪切的网页效果仍列为近似。变更渐变类型或手动指定角度后，以新的操作值为准。

### Figma 已归档样式与矢量的共享颜料

源文件含 233 条样式记录，其中 88 条活跃、145 条已归档。保留源 ID 和 `sourceArchived`，按 ID 解析旧图层引用。样式管理器标出「源稿已归档」，新图层的默认选单仅列活跃样式，已有图层继续显示当前绑定。普通节点上的共享填充和描边以关联样式为准。存在源文件明确声明的实例局部覆盖时，按覆盖字段取值。在原厂导图中，`56:56615` 的陈旧双漆缓存与当前关联的红色共享填充不同；重新打开后仍按该共享色绘制。[Figma PaintStyle](https://developers.figma.com/docs/plugins/api/PaintStyle/)

矢量的叠加填充及渐变按原路径轮廓与填充规则着色，孔洞保持透明。小型单轮廓在 1× 像素网格对齐时根据路径面积算覆盖率；缩放、旋转和高分辨率视图继续使用源矢量。用 `node --import tsx scripts/check-figma-paint-references.mjs <源.fig> <原厂颜料图目录>` 比较真实的 100 × 100 渐变和 29 × 8 共享矢量。用 `scripts/check-imported-gradients.mjs` 检查四组梯度、两种宽高比及矢量孔洞。用 `scripts/check-symbolic-material.mjs` 在预览和工程间核对浅色、深色变量与 Plus Darker、Plus Lighter、Multiply 三种混合。

在同一源文件用本机 Figma Plugin API 读取 `56:56615`，它返回一层 97% 的红色实漆和空的 `fillStyleId`。离线归档仍含历史样式 ID 和旧的双漆缓存。Forma 取归档历史样式的有效颜色，并把历史关系标作已归档。另一个节点 `492:46326` 的原生 `strokeStyleId` 有值，绑定的 Vibrant Secondary 提供 12% 的 Linear Dodge 描边。这两种源记录在新样式选单中有不同的可见状态。

### 原生名称与无标题分区

已声明的图层名可以是空字符串。导入器区分源字段缺失与显式空名，允许设计师留白的图层保存为空串。Apple Figma 原件有 11 个这样的 Section。用 `scripts/figma-source-reference` 在 Figma Desktop 直接遍历 46 页，记录各节点 ID、父节点、同级次序、实际名称、文本与实例类型。在实际另存的 Forma 文件上运行 `node --import tsx scripts/check-figma-native-tree.mjs <Figma原厂清单.json> <另存的.forma.json>`，空名字与其他名称逐字对照。实例展开后生成的子层由另一个按源主件 ID 的测试核对。
