## 一、背景与已确认的产品模型

Stage 1 已实现活体组件库三级分层（`page` / `block` / `component`）、离线/增量 AI 说明书、HTML `[data-forma-component]` 插槽化原装实例混编、Blueprint `adapt` 模块外框派生、多画板主/异常矩阵以及前置 1 轮范围收口卡。

但在真实业务持续迭代（例如「淘宝移动端」「双 11 大促」）中，设计师仍然面临三大痛点：

1. **设计稿平铺无项目单元，跨稿历史上下文断裂**：同一产品线的 `首页改版.forma`、`搜索结果页.forma`、`下单支付流程.forma` 分散在平铺文件列表中，上周已拍板的页面骨架、业务决策与选用组件无法跨稿被 Forma AI 召回。
2. **历史需求无法结构化沉淀与引用**：多轮对话刷新即丢，新需求既不能自动继承同项目、同组件库的历史需求配方，也无法通过 `@历史需求` 精准点名参考过往稿件。
3. **AI 新造 / 派生加工的好模块难以反哺组件库**：设计师在画布上微调好 AI 新造的业务楼层后，缺少一键沉淀回项目/自定义组件库并自动增量刷新 AI 说明书的闭环，导致下次还要重新生成。

### 用户已确认的核心产品决定（方案 B）

- **项目单元采用「轻量项目空间（1 项目含多份设计稿）+ 未归类草稿默认按单稿独立记忆」**：
  - 对标 Figma 的 `Project → Design File → Page` 层级，直接升级现有「本机文件」管理页（`FileBrowser`），无需先构建重型独立全屏首页工作台；
  - 随手新建的未归类草稿 **0 建项门槛**，记忆作用域自动落为 `file:<fileKey>`；一旦归入某个项目空间（`proj:<projectId>`），该稿原单稿记忆可自动随迁至项目，并立刻共享同项目全部设计稿的历史需求档案与默认组件库。

## 三、明确不做 / 本期边界（Non-Goals）

1. **不做 Stage 3 手改 Diff 自动偏好学习**：设计师采纳后手改终稿的 Diff 提炼器与 `(用户 × 组件库)` 交叉偏好面板留待 Stage 3。
2. **不做独立全屏 Home Dashboard / 多标签页编辑器外壳**：本期直接升级现有 `FileBrowser` 与编辑器顶栏/AI 面板，底层 `ProjectSpace` 数据结构为后续独立工作台预留无痛演进能力。
3. **不做云端多人实时同步**：所有项目空间、历史需求档案与工作区组件库 100% 本地 IndexedDB 离线持久存储。
4. **严格恪守零模型网关可用性红线**：未配置任何模型供应商时，项目空间管理、历史需求档案查看/搜索/手动归档/置顶/删除、`@历史需求` 选择、衍生模块沉淀到组件库与离线 AI 说明书刷新必须 **100% 本地可用，零外部网络请求**。
5. **不直接篡改官方 4 大内置组件库**：官方体系保持版本化只读；在官方库激活状态下沉淀衍生模块，默认引导落入「当前项目衍生库」或用户自定义库。

## 四、Stage 2 验收口径（Definition of Done）

1. **工程与代码质量**：
   - 通过独立只读 **Codex CLI Code Review** 并清零全部 P0 / P1 缺陷；
   - 全量 `npm test`、`npm run format:check`、`npm run build`、`npm run desktop:agent` 100% 通过。
2. **真实浏览器端到端验收**：
   - 通过受影响回归用例（`agent-canvas-chat`、`assets-libraries`、`editor-panels`、`optional-gateway`、`library-tokens`、`mcp`）；
   - 新增真实跨文件闭环 E2E 验收：
     1. 零网关离线打开「本机文件」创建项目空间「淘宝移动端」并绑定默认组件库，将文件 A 归入该项目（验证单稿既有档案自动随迁至项目）；
     2. 在文件 A 中手动/模拟采纳生成首屏并沉淀为《历史需求档案》，随后选中新造楼层一键「沉淀为组件库模块…」入项目衍生库，验证目标库组件数 +1、AI 说明书自动增量刷新且手动备注不丢、`⌘Z` 可撤销；
     3. 在同一项目下新建并打开文件 B，验证顶栏与 Forma AI 面板自动识别项目空间「淘宝移动端」，可查看并 `@引用` 文件 A 的历史需求档案，且模拟 LLM 对话请求携带 `memoryScope` + `recalledEpisodes` 并调用 `search_project_episodes` / `get_episode_details`；
     4. 导出生成画板为 React 工程并运行 `verify-exports` 独立安装构建通过；
     5. 检查深/浅双主题与短窗口下 `FileBrowser`、`PromoteModuleModal` 与 `AgentPanel` 记忆抽屉滚动、键盘焦点、Escape 与对比度无回归。
3. **版本升级与同步打包交付**：
   - 运行 `npm run release:assess` 确认升版级别（预期 `minor`：`0.10.0` → `0.11.0`），通过 `npm run release:run` 同步完成版本号/日志更新、全量门禁、桌面端 `.dmg`/`.zip` 构建及只读挂载实机验收。
