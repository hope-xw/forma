## 一、背景与真实业务痛点

截至 0.9.0 及 `2026-11-25` 组件库管理中心上线，Forma 已具备 4 大官方体系（98 组件 / 686 变体 / 10 模板）、`.fig`/`.sketch` 离线提取建库、本地主组件打包、13 家模型接入、HTML/CSS-to-Forma 双引擎与多模态视觉自审能力。但在设计师面向真实大型业务（例如**选择「淘宝移动端组件库」，描述页面、业务楼层模块及细节/异常态需求，并期望参考历史需求持续迭代**）时，仍存在四大核心断层：

1. **裸组件库缺乏语义与层级（AI 看不懂怎么选、怎么搭）**：
   - 导入的 `.fig`/`.sketch` 或团队自建库中充斥业务代号（如 `TB_Cell_V3`、`FeedsCard_Double`），缺少**页面样板（Page）/ 业务楼层（Block）/ 原子组件（Component）**三级资产分层，也缺少面向 AI 的使用说明书（何时选用、文案字数边界、组合禁忌、异常态映射）。
2. **高表现力 HTML 生成与原装组件实例割裂**：
   - 现有 `propose_html_design` 生成的新屏视觉好，但输出的是打散的普通 Frame/Text，**零复用组件库实例与 Token**；
   - 现有 `propose_design_changes` 虽然支持插入实例，但在处理库里没有的新业务模块、或者需要拆改现有楼层外框再加工时，缺乏受控的派生加工与混合装配能力。
3. **复杂多画板需求缺少「前置收口、生成零打断」的心流**：
   - 面对跨页面、多模块、含异常态的大需求，盲画易跑偏返工，而生成中途反复弹窗确认体验极差；且当前 `propose_html_design` 仅支持单画板输出，不支持主流程横向 + 浮层/异常态纵向对齐的矩阵交付。
4. **缺少跨需求的三维设计记忆（`项目空间 × 组件库 × 用户`）**：
   - 当前会话仅保留最近 10 轮纯文本对话，无法沉淀历史需求页面配方与新造衍生模块，更无法区分同一设计师在不同组件库下的差异化排版偏好。

## 二、产品目标与分期演进路线（用户已确认拍板）

### 已确认的三项核心产品决策
1. **组件库双源统一**：同时覆盖「导入存量 `.fig`/`.sketch` 自动解析建库」与「在 Forma 内原生新建、标记与演进组件库」，共用同一套活体资产与增量说明书体系。
2. **三维层叠记忆架构**：在架构上原生建模 **`项目空间（Project） × 组件库（Library） × 用户（User）`** 三个维度及 **`用户 × 组件库` 交叉偏好**，避免切换组件库时习惯串味。
3. **前置收口、一镜到底**：简单清晰需求 **0 追问直接生成**；复杂模糊多页需求在动笔前通过 **1 轮带默认方案的边界确认** 收口范围，一旦确认即全自动一镜到底完成多画板装配与自审，**生成中途零人工弹窗打断**。

### 分期实施范围

| 阶段 | 状态 | 核心交付能力 | 设计师可验证的价值 |
| --- | --- | --- | --- |

## 三、明确不做 / 本期边界（Non-Goals）

1. 本期 **Stage 1 不实施** 跨会话持久化历史需求数据库与手改 Diff 自动学习（留待 Stage 2 / Stage 3，但本期的类型契约与 `DesignChatContext.memoryScope` 必须提前就位以保证零破坏演进）。
2. 本期不支持在线直连外部 Figma API 拉取云端团队库（继续通过本地 `.fig`/`.sketch` 离线提取与 `.forma-library.json` / 本地 HTTP 订阅工作）。
3. 严禁因新增 AI 说明书功能破坏零网关可用性：在**未配置任何模型网关**时，组件库三级分类、硬契约提取、默认 AI 说明书生成、查看与手动编辑必须 **100% 纯本地离线可用，零外部网络请求**。

## 四、Stage 1 验收口径（Definition of Done）

1. **工程与代码质量**：
   - 通过独立 **Codex CLI Code Review** 并清零所有阻塞/高危缺陷；
   - 全仓 `npm test`（含新增三级分层/说明书、插槽混合编译、模块派生、工具/HTTP 契约测试）全部通过、`npm run format:check`、`npm run build`、`npm run desktop:agent` 通过。
2. **真实浏览器端到端验收**：
   - 通过既有及扩展浏览器回归（`agent-canvas-chat`、`assets-libraries`、`editor-panels`、`mcp`）；
   - 端到端实测模拟「淘宝风格移动端电商组件库（含页面/楼层/原子组件/异常态）」完整流程：
     1. 组件库管理中心查看/编辑/刷新自动生成的 **AI 说明书**；
     2. 在 **Forma AI** 面板选定该组件库，提交复杂需求触发 **1 轮《生成范围确认卡》**，点击 **「确认并直接生成」**；
     3. 一次性在画布生成 **主流程画板 + 纵向对齐的异常态画板**；验证画板中既有 **受保护原装组件实例**（保留 `instance` 元数据与变体属性），又有 **绑定了库 Token 变量的新造业务模块**；
     4. 执行「采纳 → 选中文本手改 → 切换组件变体 → `⌘Z` 单步撤销 → 导出 React 工程独立构建」，全程通过并归档实拍与统计证据。
