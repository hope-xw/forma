## 首个产品验收案例

1. Web 管理页面：表格、表单、弹窗，桌面 1440/1024 与窄容器行为明确。
2. H5 页面：390/375 宽度、触控点击、溢出滚动与返回。
3. 设计系统页面：本地/共享组件、实例文案覆盖、变量别名、明暗主题，主件更新不抹掉覆盖。
4. 复杂原型：两个 Flow；点击打开浮层；条件分支修改变量；切换交互组件状态；滚动保持；返回/重置确定。
5. Agent 接续：先生成；人工改 A/B；Agent 仅修改 C；撤销 C；A/B 保持；基准过期明确报错。
6. 生产交付：下载完整 React/TS 工程，干净目录安装和构建，逐条核对静态结构、交互和资源；再处理一次设计更新。

## “无损”可执行定义（建议指标，需基准确认）

- 结构：约定支持范围内的组件、实例、覆盖、Token 和资源引用保留率 100%；不支持项必须阻止发布或明确逐项降级，不能静默丢失。
- 几何：固定浏览器版本、字体文件、DPR 后，主要边界与间距误差不超过 1 CSS px；文字换行一致。两份原生样例合计 20 个画板已达此门槛，其他设计稿需按同口径实测。
- 响应式：375/390/768/1024/1440 宽度，加长文案和增删内容；按定义换行、填充、溢出，无非预期重叠。
- 行为：每条声明的交互路径、条件和重置规则全部通过自动化测试；模型不推测未定义业务逻辑。
- 工程：独立可安装构建；严格 TS 无错误；输出不依赖编辑器内部运行时；资源完整、语义标签与焦点行为可验收。
- 可维护：稳定节点到代码映射，组件独立模块，Token 独立输出，依赖与构建入口明确；设计更新不会覆盖开发者的业务扩展。

## 性能门槛待基准

分别测 100/1000/10000 图层的加载、选取、拖动、缩放、内存、序列化与导出；记录设备/浏览器/字体/资源。不能在没有采样前承诺万层 60 fps。数据将决定虚拟化和渲染后端演进。
