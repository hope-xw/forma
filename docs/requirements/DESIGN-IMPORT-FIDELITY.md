# 设计文件导入的保真与恢复验收

最近更新日期：2026-11-23  
状态：草案  
关联源码：`src/domain/{document,node,pages,rich-text,library-schema,component-masters,design-system}.ts`、`src/editor/{App,FileBrowser,CanvasNode}.tsx`、`src/infrastructure/storage.ts`、`src/runtime/`、`src/compiler/`、`electron/main.mjs`  
验收方式：在源工具冻结输入、结构清单与截图，经正式文件入口导入，完成逐层对账、编辑、重开、预览和独立工程回放。以下场景为验收设计。第 1 节记录 2026-11-22 的实施前基线。已发布版本的实测结果见[编辑器验收记录](../EDITOR-ACCEPTANCE.md)。

## 1. 先处理会改变稿件的现有限制

| 路径 | 已核对的行为 | 导入工程需要做的事 |
| --- | --- | --- |
| `src/editor/FileBrowser.tsx`、`src/editor/App.tsx`、`src/main.tsx`、`electron/main.mjs` | 文件管理器读取 JSON 后建本机副本。画布另有载入当前文件的路径。桌面主进程按 UTF-8 同步读文件、按文本交给渲染器。 | 按字节识别源格式，Web 与 Electron 共用转换及校验。跨工具导入创建独立稿，只有在数据库提交成功后才切换；产品测试须分别走文件管理器、画布文件菜单、桌面打开入口。保留 Forma 原生文件原有操作。 |
| `src/domain/document.ts`、`pages.ts`、`scene-index.ts` | 活动页内容存根级 `nodes`，非活动页内容存 `pages[].nodes`。每页最多 10,000 层、100 页、父链最多 256 层。图层 ID 全文档唯一。场景按数组顺序组装同父兄弟，图层树依布局可能反向展示。 | 映射源页、父 ID 和同级绘制顺序。单列合成节点、模板节点与因实例展开生成的节点。通过重叠色块与点选验证视觉顺序。按源节点数和展开后节点数各预算一次。 |
| `src/domain/node.ts`、`transforms.ts`、`rich-text.ts` | 宽、高范围 1–10,000；平移、中心旋转及镜像有字段，一般仿射剪切没有持久字段。文本限 50,000 个 JS 字符串单元，富文本用 JS 切片。每层最多 16 个附加 paints、8 个阴影，每个渐变 2–8 色标。 | 对零高线、半像素、缩放与剪切、带方向的多次嵌套矩阵、九色标逐项验证。遇到上限必须定位具体属性。需要扩 schema 时同步改保存、布局、运行时及生成器；未经验证的裁剪、取整、合并填充均记录为损失。 |
| `src/domain/library-schema.ts`、`component-slots.ts`、`component-masters.ts` | 单库上限 1,000 个组件、50,000 个模板节点，单组件 200 个变体，单变体 1,000 个节点且恰有一个根。模板内必须有唯一 `templateKey`，禁止直接放 `instance`。主件同步依据库、文档、根和模板键。 | 先建立主件、模板键和依赖图，再绑定实例、嵌套槽与覆盖。以原工具中改主件后的结果校验默认值、显式覆盖和重置行为。外部库无法解析时保留来源标识、已取得的外观及问题位置。 |
| `src/domain/design-system-schema.ts`、`design-system.ts`、`images.ts`、`fonts.ts` | 原生样式有 paint/text/effect/grid 四种，支持变量/别名/模式。位图用内容摘要 ID 和 PNG/JPEG/WebP/GIF data URI；单项最多 12,000,000 个字符串单元。内嵌字体限 TTF/OTF，单项最多 24,000,000 个字符串单元。 | 样式表、节点绑定和覆盖逐项对账。按源图像内容核对字节、ICC 和复用次数。缺字体区分“未安装”“未嵌入”“缺特定字形”；保留源家族、字重、文字及拟替换项。转码必须单列。 |
| `src/infrastructure/storage.ts`、`src/compiler/file-project.ts`、`src/compiler/runtime.ts` | 同一 IndexedDB 事务更新稿件和最近文件目录，更新现存稿时保留上一版并检查 generation。React 导出逐页生成路由，Section 和 Slice 在交付时有专门解包规则。 | 任何新增导入清单、资源和来源载荷都需纳入原子发布与清理设计。逐页打开再保存，核对副本和交付目录；单独列明 Section/Slice 的编辑树与工程树预期。 |

只读探针在当前代码上验证了四个容易漏测的行为：未知根字段 `importSource` 经 `parseDocument` 后消失，页名 `" 页 "` 会收成 `"页"`，零宽节点与 50,001 单元的文本均被拒绝，活动页重复声明节点会报“活动页面内容重复”。来源清单或未支持属性需要有正式持久化契约，验收应包含下载后换设备重开。

给定素材目录实际包含 150 个 PNG 和一个 SVG。其中 137 条相对文件路径含 U+100EC3，为补充平面私用字符。在本机用 `createNode("text")` 构造 `键\u{100EC3}盘`、将 `textRuns` 的加粗范围设为 `[1,3)`，经 `parseDocument` 与 `textParts` 仍得到三个片段，中段完整。这个探针检验了 Forma 现有字符串处理，源格式解码、字体字形覆盖和界面保存仍需各自跑通。

## 2. 冻结真值与计量口径

1. 每个样本记录源工具名/构建号、容器/格式版本、文件 SHA-256（在线输入记录文件 key、version 和抓取内容摘要）、页与节点 ID、字体版本、色域、系统、缩放、DPR、采集时间。各格式分别包含最简稿、带组件样式的真实多页稿、超出表示能力的稿。保留样本使用范围；Apple 原件与截图可在本机权限范围内核验，仓库回归用自制可分发样本。
2. 真值应独立于被测转换器。用 Sketch 自身的检查/渲染能力，或 Figma 内独立只读清点及原工具导图。冻结页面顺序、父子及同级次序、源字符串与样式区间、主件/实例引用、样式/变量连边和资源摘要。官方读取路径缺字段时，登记“不可观测”，用受控源文件及源端人工核对补证。缺少原工具输出时，标明“结构验证”或“视觉待测”。
3. 清单按页、源类型和特性累计。每个源节点、每条实例/样式/覆盖边、每个实际出现的样式属性各记一次处置结果。节点合并、拆分、实例展开用显式多对多映射，源模板账与实例展开账分开；隐藏、锁定、无可见像素的层进入结构分母。被截图包住的全部子孙仍要逐一入账。
4. 单独报告四类结果：原生可编辑、保留近似表现（列明损失）、只有参考外观或原数据、阻断。原生覆盖率分母为所导入范围的全部源节点；可解析引用率分母为所有源引用，单列远程不可取的引用。报告每类分子/分母和源 ID。分母为零写“无样本”。页面选择必须同时列出整文件、选定页和引入依赖的三组清单。
5. 登记为“完整兼容”的版本和特性范围内，页面、层级顺序、文字、可编辑主件/实例、样式及绑定的指定断言全部通过；未交代损失、不可解释的节点、重复 ID、错绑、悬空引用均为 0。任何关键对象降级都在打开前显示受影响数量和处置，可预览、可取消。一次有提示的降级计入诊断成功，保真指标继续记录损失。

## 4. 图像证据怎样判定

- 源工具→Forma 单列。锁定装载字体、色域、渲染尺度、透明背景与视口。覆盖每个核心特性的自制黄金画板，再从每份真实套件按“组件/页面/深浅/缺依赖/极端几何”分层取样；记录每层样本 ID 与已测/总画板数。对纯色内部与遮罩 Alpha 逐点比较（归一到同一色域后，8-bit 通道误差 ≤2）。对有已知栅格真值的普通块，建议初始门槛为每幅 RGBA 最大通道差 >16 的像素 ≤0.5%，并对图标、文本、蒙版逐个 ROI 应用相同门槛。发生超限时保留差异图与源层 ID，由像素定位到属性，不能用整稿平均数冲抵。特殊材质、字体栅格化差异留独立证据。先以源工具重复输出校准；任何新容差都随版本留理由与受影响画板，原数保留。
- Forma 画布→预览→独立工程分段对照。沿用现有脚本的同引擎 DPR=1、逐层边框最大误差 ≤1 CSS px、可测文字行数一致、预览/工程 RGB 最大通道差 >16 的像素占每幅面积 ≤0.01%。有 Section、Slice、隐藏层时先用固定语义说明预期可见树，透明内容补测 Alpha；源清单始终保留这些节点。文字再检查关键运行区间的断行索引，避免行数相同、断点错误。
- `scripts/check-render-parity.mjs` 目前只遍历 `aura-showcase` 与 `mobile-studio`。实施时增加“从用户入口打开实际源文件并下载”的输入方式，按源 ID 定位，另用独立结构清点和源截图校验。已有 20 个原生画板的记录只可作 Forma 内部回归。[现有验收与图像证据](../EDITOR-ACCEPTANCE.md)

## 5. 成本、平台及复测工序

| 要测的成本 | 统一条件与门槛 |
| --- | --- |
| 分阶段导入 | 记录读取、解压/解码、引用解析、素材就绪、校验、提交、首个可编辑画板、全部页完成时间。记录源压缩/展开字节、源/展开节点和图片解码像素数、主/Worker 峰值内存。样本含平铺 10,000 层、8,288 层复杂稿、共享大图及实际套件；连续运行 6 次，首轮冷启动单列，余项给中位/最慢值。格式版本的首轮读数供立档；以后同机同稿中位耗时与峰值内存相对冻结可用版的增加超过 20% 须定位后再放行。 |

实施期先运行 `npm test`、`npm run format:check`、`npm run build`。生产预览上运行 `FORMA_URL=http://127.0.0.1:4173 npm run test:browser -- layer-tree complex`；再逐引擎用 `npm run test:browser` 从真实 UI 生成 ZIP、`npm run test:exports` 独立安装构建运行、`node scripts/check-render-parity.mjs` 核对渲染。macOS 加跑 `node scripts/check-desktop-workflows.mjs` 和新增的两类外部文件打开场景。以上既有命令须在导入场景接入后才产生该能力的证据。

每次候选发布保存样本清单、批准的特性/版本范围、逐项处置与引用表、关键交互日志、逐画板差异、资源与源文件摘要、计时和平台结果。源码、架构、规格、交接和验收记录须标明实际放行的格式及版本。阻断、无基准、不可取依赖和已知近似均保留具体文件与节点路径，以便后续用同一位置复测。

## 6. 已实测的上下文材质

以 sketchtool 2026.3.1 (234013) 对真实 Apple Sketch 封面原稿和本机临时变体导图。数字 “27” 的上游是可编辑文字层，原层导出的 SVG 有一个文字元素和三个滤镜，单层 PNG 为 640 × 382。把该 PNG 按普通 Alpha 叠回原背景，640 × 640 的整图有 78,141 像素超过 16 级。保留原图中受文字影响的 120,565 个像素，叠回隐藏文字的同一背景后，所有像素通道差为 0。修改背景后复用旧合成结果，超过 16 级的像素升至 118,979。这组数据用于回归编辑文字或改变背景后的重新合成。源档、临时变体及导图留在本机，仓库证据仅记录源摘要、图层 ID、测量条件与计数。[原厂复跑脚本](../../scripts/check-sketch-material-context.py) · [测量记录](../evidence/2026-11-23/apple-sketch/material-context.json)

Figma 对照分别采集完整组件、可复用按钮和玻璃叠层。在同一组件的透明底区域，Linear Burn 保留源漆的一次 Alpha。已有图层覆盖的区域按画稿层序和测得的几何计算混合。回归件移动下方色块或改变父级填充后重新计算结果。源工具导出独立图与实际整文件预览均在白底以 DPR 1 比对。独立 React 工程使用同一正式下载包和原文件路由复核。[原厂只读采集器](../../scripts/figma-source-reference/code.js) · [透明背板回归](../../tests/layer-blend.test.ts) · [整文件三引擎读数](../evidence/2026-11-23/apple-figma/alert-blending.json)

原生结构复跑可在本地 Figma Desktop 注册只读采集器，打开同一文件后点击「另存原厂图层清单」。采集器按原厂页序走访每个节点，记录 ID、父 ID、兄弟次序、原始名称、原始类型以及文字的完整 Unicode 字符串，遇到实例保留实例本身。用以下命令对照由 Forma 界面新保存的完整副本。

```sh
node --import tsx scripts/check-figma-native-tree.mjs \
  output/playwright/apple-figma-0.8.3/material-controls/native-tree.json \
  output/playwright/apple-figma-0.8.3/apple-figma.forma.json
```

此原件的分母为 46 页、10,657 个手工定义的节点，其中 1,807 个为文本、4,101 个为实例。原厂包含 11 个无标题 Section。正式版打开原件并保存的 411,299,399 字节副本通过全部严格断言，包含这 11 个空字符串。嵌套实例生成的后代由主件映射与实例覆盖回归另行核验。[原厂树对账记录](../evidence/2026-11-23/apple-import-0.8.3/native-tree.json)
